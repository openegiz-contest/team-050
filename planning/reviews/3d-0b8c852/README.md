# Проверка 3D-ветки сокомандника

Дата: 24 октября 2026 года. Ветка: `codex/3d-map-correct-vehicle-placement`. Коммит: `0b8c852e5f77591bf2a39a55fc57b34058c2c25a`. Автор изменения — Дильназ Шамханова. Отдельный checkout: `C:\Users\user\Documents\Carier\team-050-3d-preview`.

## Найденные ограничения

### P1. 3D-положение машины отличается от телеметрии

В `team/mine/ui/src/main.ts`, `updatePositions`, переменные `leader`, `spacingUnits` и последующее устранение пересечений искусственно меняют координаты машин. Это не просто боковое смещение метки: машина продвигается или отодвигается вдоль дороги. Масштаб карты влияет на это смещение.

Проверка использует функцию прямо из исходника ветки. Три машины на `P>J1` с `edge_progress` 0.10, 0.08 и 0.04 при масштабе 0.6 дают визуальные положения **1.00, 0.00 и 0.00**. Первая нарисована в конце дороги, хотя прошла только 10%. Данные: [placement-reproduction.json](placement-reproduction.json).

Перед объединением нужно сохранять физическую позицию по телеметрии. Для читаемости можно разносить подписи/иконки поперёк дороги или показывать группу/очередь, отделив этот условный символ от истинного положения. Тест: масштабирование не меняет прогресс машины вдоль дороги.

### P2. Выездные машины не связаны с 3D-положением

`syncGLBModels` перебирает только `truck-*`; два пикапа привязаны к R1 и R2. В цикле SVG-машин 3D также обрабатываются только самосвалы. Двойники `service-01`, `service-02`, `tow-01` не используются для их движения в 3D. В 2D эти машины уже отображаются. Подтверждено чтением кода; выезд и эвакуация в этой проверке не запускались.

Нужно добавить движение по их `edge_id` / `edge_progress`, состояния и цель. Статические декоративные пикапы отделить от управляемых сервисных машин.

### P2. Нужна индикация технических состояний в 3D

Класс 3D-самосвала выбирается из `returning / loaded / waiting`, неисправность и профилактика не влияют на обозначение. GLB-самосвалы используют исходную окраску материалов, поэтому легенда цветных 2D-иконок не даёт того же различения. Подтверждено чтением кода; отдельный тест вызова отказа не выполнялся. Добавить маркеры неисправности/обслуживания и загрузки, не меняя физическую позицию.

## Локальная нагрузка и воспроизведение

После перезапуска Ditto сбросился уровень логирования; восстановлен `warn` из `deploy/compose/init/logging.json`. Старый параллельный `mosquitto-target-connection` временно переведён в `closed`: он пытался дополнительно читать `extraFields` для каждой записи и создавал ошибки обогащения. Собственный `team050-target`, входной MQTT и сохранения остались активны. На работающем стенде получены согласованные кадры из 35 двойников; периодические задержки свежести на ноутбуке с 8 ГБ ещё наблюдаются. Полный повтор инициализации платформы снова открывает стандартный канал.

Текущий просмотр: http://127.0.0.1:8088/ → 3D. Для продолжения смены нажмите «Продолжить». Изменения интерфейса переживают обычный restart контейнера, но пересоздание контейнера вернёт интерфейс установленного образа main.

Повторно установить именно этот предварительный интерфейс после сборки в отдельном checkout:

```powershell
docker cp C:\Users\user\Documents\Carier\team-050-3d-preview\team\mine\ui\dist\. openegiz-mine-web-1:/app/ui/dist/
```

```bash

```
