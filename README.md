# Карьер · Team 050

Цифровой двойник условного карьерного участка по мотивам Актогая. Диспетчер назначает маршруты 20 самосвалам и управляет сменой; механик обслуживает и ремонтирует технику. Состояние модели публикуется в OpenEgiz/Ditto и показывается в диспетчерской 2D/3D.

Расстояния, загрузки, время операций, расход топлива и сменный план — параметры учебной симуляции, а не производственные нормы.

## Запуск с нуля

### Требования

Окружение конкурса: Ubuntu 24.04 amd64, Docker Engine 29.1.3, Docker Compose 2.40.3, 8 vCPU, 16 ГиБ RAM и 60 ГБ диска. Docker Compose v2 и доступ в интернет нужны для сборки и загрузки образов при первом запуске. На хосте не требуются Go, Node.js, `make` или отдельная установка OpenEgiz.

На Windows запускайте команды в Ubuntu/WSL2 с включённой интеграцией Docker Desktop. Выделите Docker не менее 6 ГБ памяти; при меньшем объёме используйте режим экономии памяти ниже.

### Команды

В терминале выполните:

```bash
git clone https://github.com/openegiz-contest/team-050.git
cd team-050
docker info
docker compose version
bash scripts/team-up.sh
```

Скрипт при первом запуске автоматически создаёт локальные секреты в `deploy/compose/.env`, собирает Go-сервисы и интерфейс, загружает и запускает платформу, готовит 35 двойников и ждёт готовности приложения. Не редактируйте `.env` и не вводите секреты вручную. Первый запуск требует интернета и может занять до 75 минут в окружении конкурса.

Когда скрипт сообщит, что смена подготовлена, откройте [http://127.0.0.1:8088](http://127.0.0.1:8088). Проверить готовность интерфейса можно командой:

```bash
curl -fsS http://127.0.0.1:8088/readyz
```

Двойники также доступны в OpenEgiz в разделе **Twins**. Используйте адрес `127.0.0.1`.

### Режим памяти

При доступной Docker-памяти менее 6 ГБ скрипт запускает основные службы последовательно, оставляя Grafana и дополнительный OpenEgiz API выключенными. Диспетчерская, симуляция и история остаются доступны. Этот режим можно включить явно:

```bash
TEAM_LOW_MEMORY=1 bash scripts/team-up.sh
```

Чтобы запустить полный стенд вместе с Grafana и дополнительным OpenEgiz API:

```bash
TEAM_AUXILIARY=1 bash scripts/team-up.sh
```

В полном режиме Grafana доступна по адресу [http://127.0.0.1:3000](http://127.0.0.1:3000), дашборд **«Карьер — Team 050»**, пользователь `admin`. Пароль создаётся локально и хранится только в `deploy/compose/.env`.

## Работа со сменой

1. Выберите самосвал. Назначьте шаблон M1–M6 или постройте индивидуальный маршрут по соседним узлам карты от E до C; подтвердите его кнопкой **«Назначить машине»**. **«Распределить по M1–M4»** назначает по пять машин на каждый основной маршрут.
2. Нажмите **«Начать смену»**. Самосвалы выезжают из гаража P, проходят погрузку, перевозку, очереди и разгрузку. Смена длится 12 модельных часов. Управляйте временем кнопками **«Пауза»** и **×1 / ×10 / ×30 / ×60**. При ×30 полная смена занимает около 24 минут, если компьютер успевает считать модель.
3. На карте следите за местоположением и состоянием машин. Вкладка **«Журнал событий»** показывает операции и команды. Вкладка **«Погрузка и топливо»** показывает загрузки, расход, заправки и ожидание. План считается по переработанной, а не только доставленной руде.
4. В разделе **«Отчёты смен»** после 12 часов доступен JSON-отчёт. Кнопка **«Повтор»** запускает новый прогон с теми же исходными маршрутами, планом, топливом, массами загрузок и расписанием отказов. Если смена идёт, сначала поставьте её на паузу. Старые отчёты сохраняются.

### Поломки, ремонт и профилактика

Во время смены диспетчер может вручную вызвать лёгкую, среднюю или тяжёлую поломку. Случайные отказы также включены. После первых 30 модельных минут у каждой машины моделируются потенциальные отказы; выполненные события видны в журнале и на карте.

Переключитесь на роль **Механик** и выберите восстановление:

- **Лёгкая поломка:** выезд сервисной машины и обслуживание на месте.
- **Средняя поломка:** направить самосвал на R1/R2 для ремонта своим ходом.
- **Тяжёлая поломка:** вызвать эвакуатор и выбрать ремонтную площадку.
- **Профилактика:** отправить сервисную машину к исправному самосвалу. После завершения профилактики он защищён от случайной поломки на два модельных часа.

Ремонт и профилактика возвращают технику к работе. Зарегистрированные ручные отказы сохраняются; команда **«Повтор»** воспроизводит их. Чтобы полностью очистить состояние и архив, остановите стенд и удалите его Docker volumes:

```bash
docker compose --env-file deploy/compose/.env -f deploy/compose/docker-compose.yml -f team/mine/compose.yml down --volumes
bash scripts/team-up.sh
```

Удаление volumes необратимо удаляет отчёты, команды, состояние симуляции и данные истории. Случайные отказы в новых сменах останутся включены.

### Погрузка и топливо

Масса полной загрузки случайно выбирается в диапазоне 230–250 т и фиксируется на рейс. Остаток топлива показывается в карточке самосвала и во вкладке **«Погрузка и топливо»**. При уровне ниже 25% самосвал автоматически направляется на ближайшую заправочную площадку R1/R2; механик может назначить её вручную. Заправочные очереди не занимают ремонтные бригады. Если топливо закончилось в пути, вызовите эвакуатор до площадки.

Параметры погрузки, топлива, случайных отказов и повторяемости: [операционная модель](planning/ОПЕРАЦИОННАЯ_МОДЕЛЬ.md). Действия механика и правила сохранения груза: [поломки и ремонт](planning/ПОЛОМКИ_И_РЕМОНТ.md).

## Остановка, журналы и повторный запуск

Обычная остановка сохраняет состояние, историю и отчёты:

```bash
bash scripts/team-down.sh
```

Повторный запуск:

```bash
bash scripts/team-up.sh
```

Список служб и последние журналы:

```bash
docker compose --env-file deploy/compose/.env -f deploy/compose/docker-compose.yml -f team/mine/compose.yml ps
docker compose --env-file deploy/compose/.env -f deploy/compose/docker-compose.yml -f team/mine/compose.yml logs --tail=80 mine-engine mine-web mine-setup
```

Закрытие вкладки браузера не останавливает симуляцию. После перезапуска незавершённая смена восстановится на паузе.

## Что моделируется

- 20 рабочих самосвалов, 4 места погрузки, 3 дробилки и 2 ремонтные площадки; в концепции дополнительно предусмотрены пять резервных машин.
- 35 двойников OpenEgiz в пространстве `org.openegiz.team050`; телеметрия и команды проходят через MQTT и Ditto.
- Индивидуальные и шаблонные маршруты, погрузка, очереди, разгрузка и переработка.
- Ручные и воспроизводимые случайные отказы, обслуживание, ремонт, эвакуация, профилактика и заправка.
- 2D-карта и условная аксонометрическая 3D-карта показывают одну симуляцию.

Дневной план 93–95 тыс. т — командный ориентир модели. Первый архивный 12-часовой прогон выполнил 92 161,35 т переработанной руды до утверждения диапазона. Источники характеристик и допущения: [данные по предприятию](planning/sources/ENTERPRISE_SOURCES.md), [данные техники](planning/sources/EQUIPMENT_SOURCES.md), [расчёты модели](ПАРАМЕТРЫ_СИМУЛЯЦИИ.md).

## Ограничения

Не реализованы пять резервных самосвалов, роль начальника смены, многопользовательская сессия, износ, поломки дробилок, расход топлива сервисных машин, уклоны, столкновения и физические дорожные заторы. Карта схематична, не геодезическая. Верхняя загрузка 250 т — допущение модели, а не паспортная рекомендация для реальной техники.
