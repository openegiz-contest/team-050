# Карьер · Team 050

Первая версия рабочего места диспетчера на **Go + TypeScript** для OpenEgiz. Условный участок по мотивам Актогая: 20 самосвалов CAT 793D, четыре экскаватора Hitachi EX5600-6 и три независимые дробилки. Карта, расстояния и режимы работы — параметры модели.

## Запуск

Нужны Docker с Compose v2.24.4 или новее и около 6 ГБ памяти для Docker. На Windows запускайте команды в Ubuntu / WSL2 с включённой интеграцией Docker Desktop. Рабочую копию лучше хранить в домашнем каталоге Ubuntu, например `~/Carier/team-050`. Требования платформы: [OPENEGIZ.ru.md](OPENEGIZ.ru.md).

Из корня репозитория:

```bash
bash scripts/team-up.sh
```

Скрипт создаёт секреты при первом запуске, собирает интерфейс и Go-сервисы, запускает платформу и создаёт 32 двойника. Установка Go, Node.js и make на хост не требуется. При первом запуске нужен доступ к реестрам образов и зависимостей. Порты по умолчанию доступны только на этом компьютере.

Если Docker выделено менее 6 ГБ, скрипт запускает службы Ditto последовательно и оставляет Grafana и дополнительный OpenEgiz API выключенными. Диспетчерская, Ditto, MQTT, MongoDB, Telegraf и InfluxDB работают; история сохраняется. Такой режим можно включить явно: `TEAM_LOW_MEMORY=1 bash scripts/team-up.sh`. Для полного стенда используйте `TEAM_AUXILIARY=1 bash scripts/team-up.sh`; рекомендуемые 6 ГБ памяти Docker сохраняются. При обновлении в этом режиме текущая смена сохраняется и серверы перезапускаются.

**Открыть: [диспетчерская — 127.0.0.1:8088](http://127.0.0.1:8088).**

На локальном стенде Windows доступ через `localhost` давал задержку около 3 секунд на запрос; тот же запрос через `127.0.0.1` занял 41 мс. Поэтому для диспетчерской используется явный IPv4-адрес. Если вкладка была открыта до обновления, откройте ссылку выше заново.

В полном режиме Grafana: [localhost:3000](http://localhost:3000), дашборд «Карьер — Team 050». Логин `admin`; сгенерированный пароль находится в `deploy/compose/.env`, не в Git. Двойники доступны в приложении OpenEgiz → Twins. В режиме экономии памяти используйте прямую ссылку на диспетчерскую выше.

## Первая смена

1. Все 20 рабочих машин находятся в гараже P с пустыми кузовами. Смена подготовлена, время стоит.
2. Выберите машину, затем шаблон M1–M6 или «Свой маршрут». Для своего пути нажимайте соседние узлы карты: начните с E и закончите C. Посмотрите расстояние, оценку движения и переход к назначению, затем нажмите «Назначить машине».
3. Для быстрого начала кнопка «Распределить по M1–M4» предлагает по пять машин на каждый основной шаблон. Это начальная раскладка, не оптимальное распределение; C2 получает поток от двух погрузок. Назначения можно менять по отдельности.
4. Нажмите «Начать смену». Машины выезжают через P–J1, занимают очереди, грузятся, перевозят руду, разгружаются и возвращаются. Изменение пути в движении применяется на безопасной точке.
5. Используйте паузу и скорости ×1/×10/×30/×60. Смена — 12 модельных часов; при ×30 это примерно 24 минуты без пауз, если компьютер успевает обрабатывать модель.
6. Следите за бункерами, очередями и переработанным тоннажем. «Журнал событий» показывает производство и статусы команд. Доставленная руда ещё не считается переработанной.
7. После 12 часов откройте «Отчёты смен» и скачайте JSON. «Повтор» создаёт новую смену с исходными назначениями. Завершённые отчёты сохраняются.

Согласованный сменный план — 93–95 тыс. тонн переработанной руды. Новая независимая смена получает значение в этом диапазоне; повтор сохраняет план для сравнения решений. Начатая смена без плана при обновлении получает 94 000 т. План и процент выполнения видны в верхней карточке и сохраняются в новых отчётах. Старые архивные отчёты не изменяются.

## Поломка и ремонт

В шапке доступен выбор **Диспетчер / Механик**. Диспетчер выбирает лёгкую, среднюю или тяжёлую поломку. Механик отправляет сервисную машину на лёгкий ремонт и профилактику на месте, направляет самосвал со средней неисправностью на R1/R2 или вызывает эвакуатор при тяжёлой. По одной общей бригаде на площадку и её сервисную машину; выезд и стационарный ремонт не выполняются одной бригадой одновременно. Диагностика — 5 минут; выездная работа — 15, средний ремонт — 50, тяжёлый — 150 минут. Груз сохраняется. Время движется только в запущенной смене; паузой управляет диспетчер.

Подробные шаги, правила груза, очередей и повтора: [Поломки и ремонт](planning/ПОЛОМКИ_И_РЕМОНТ.md). Все три уровня вызываются вручную; случайный генератор и износ пока не включены.

## Карта 2D / 3D

Кнопки 2D / 3D меняют представление одной смены. Ракурс 3D фиксированный, высоты условные. Модели самосвалов, две сервисные машины и эвакуатор следуют положению двойников. Точка под подписью — физическое положение; изменение масштаба не перемещает технику вдоль дороги. Если подписи близки, счётчик `+N` открывает список машин в этой группе.

Л/С/Т обозначают лёгкую/среднюю/тяжёлую неисправность, ТО — профилактику. Г — груз, П — пустой кузов. Неисправности отмечены красным, профилактика — фиолетовым; состояние дополнительно видно в карточке машины и списке группы. Нажатие на служебную машину показывает её состояние, положение и цель.

Доступны масштаб, перетаскивание и разворачивание карты. В развёрнутом виде диспетчер управляет паузой кнопкой на карте; Escape сворачивает её. При недоступной GLB-модели остаётся схема и доступен повтор загрузки. Рабочий режим не зависит от успешности загрузки моделей.

## Остановка и повторный запуск

```bash
bash scripts/team-down.sh
```

Volumes, история, команды и отчёты сохраняются. Повторный запуск — `bash scripts/team-up.sh`. Восстановленная незавершённая смена стоит на паузе. Закрытие вкладки не останавливает серверную симуляцию.

Состояние и журналы:

```bash
docker compose --env-file deploy/compose/.env -f deploy/compose/docker-compose.yml -f team/mine/compose.yml ps
docker compose --env-file deploy/compose/.env -f deploy/compose/docker-compose.yml -f team/mine/compose.yml logs --tail=80 mine-engine mine-web mine-setup
```

`make up` / `make down` также учитывают командный overlay. Платформенный `make example-mine` для этой модели не требуется. Удаление volumes уничтожает историю; обычная остановка сохраняет данные.

## Устройство

```text
Go mine-engine → MQTT → Ditto → MQTT events → Go mine-web → SSE → 2D/3D-карта
Браузер → Go mine-web → Ditto live message → MQTT → Go mine-engine
Ditto → MQTT events → Telegraf → InfluxDB → Grafana
```

Браузер получает производственное состояние из подтверждённых двойников Ditto. Один серверный расчётный цикл обслуживает смену, сеть работает отдельно. Снимки и идемпотентные команды хранятся в SQLite, томах `team050-engine` и `team050-web`.

Инициализатор настраивает отдельное исходящее MQTT-соединение Ditto `team050-target`, ограниченное пространством `org.openegiz.team050`. Оно публикует события и live-команды в `team050/ditto/...` без `extraFields`: все значения кадра уже находятся в событии. Это исключает дополнительное чтение двойника при каждой публикации. Telegraf получает историю из того же канала, определяет `thingId` по topic протокола Ditto и сохраняет прежние имена полей и measurement. На отдельном командном стенде стандартный `mosquitto-target-connection` закрывается инициализатором: он дублирует события и выполняет лишние `extraFields`-чтения. Для общего стенда с другими приложениями задайте `TEAM_KEEP_LEGACY_TARGET=1` перед `team-up.sh`: старый канал будет открыт. Входная телеметрия, собственный канал Team 050 и история сохраняются. При инициализации также восстанавливается уровень журналирования Ditto `warn`.

## Границы первой версии

Рабочие места диспетчера и механика с одиночным переключением ролей, 2D/3D-карта, три уровня ручных поломок, выездное обслуживание и эвакуация. R1/R2 работают как ремонтные площадки с очередями и общими выездными бригадами. Случайные отказы, износ, отказы дробилок, расход топлива, ввод пяти резервных машин, начальник смены и совместная игра относятся к следующим этапам. Дороги двусторонние; столкновения, уклоны и дорожные заторы не моделируются. Очереди рассчитываются у оборудования.

Версия предназначена для локальной диспетчерской сессии. Первый полный прогон сохранён в `planning/runs/`; команда приняла первый интерфейс и диапазон сменного плана. Проверки 3D и текущих исправлений: `planning/reviews/`. Пакет для перевода: [localization/README.md](localization/README.md). Показанные частоты обновлений зависят от ресурсов локального стенда.
